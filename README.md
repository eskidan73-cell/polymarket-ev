# polymarket-ev

Учебный проект: находить и **проверять** ценные ставки (+EV) на рынках
предсказаний. Считает справедливую цену, ищет расхождения между Polymarket и
Kalshi и — самое главное — умеет честно проверить, была ли найденная «ценность»
реальной или просто шумом.

> Это инструмент **понимания и анализа**, а не автоставочник. Он ничего не
> ставит и никуда не логинится — только читает публичные данные и считает.
> «Нашёл edge на экране» ≠ «заработал»: см. раздел про бэктест.

## Что внутри

```
polymarket-ev/
├── README.md          # этот файл
├── requirements.txt   # зависимости (requests)
├── calculator.py      # ЯДРО: де-виг, edge после комиссии, Келли
├── scanner.py         # тянет рынки Polymarket (публичный API)
├── matcher.py         # матчинг Polymarket <-> Kalshi + межплощадочный edge
├── backtest.py        # логирование сигналов + калибровка / P&L / Brier
└── tests/             # юнит-тесты ядра (pytest)
```

Начинай знакомство с `calculator.py` — там вся математика в трёх функциях.
Остальное — «водопровод» вокруг неё.

## Установка

Нужен Python 3.10+.

```bash
pip install -r requirements.txt
```

Для тестов: `pip install -r requirements-dev.txt && pytest tests/`

## Как запускать по шагам

**1. Проверить ядро расчёта** (на примере из обсуждения: кэфы 1.75 / 2.20, цена 50c):

```bash
python calculator.py
```

**2. Стянуть живые рынки Polymarket:**

```bash
python scanner.py
```

**3. Сопоставить с Kalshi и увидеть расхождения:**

```bash
python matcher.py
```

**4. Бэктест — проверка, что твой сканер не врёт:**

```bash
python backtest.py demo     # записать демо-сигналы (посмотреть формат)
python backtest.py update   # дописать исходы по закрывшимся рынкам
python backtest.py          # посчитать калибровку, P&L и Brier
```

## Как это работает (коротко)

1. **Цена рынка** — берём с публичного API (Polymarket Gamma / Kalshi).
2. **Эталон** — справедливая вероятность. Либо де-виг из линии БК, либо
   вторая площадка (Kalshi) как ориентир.
3. **Edge** — сравниваем цену с эталоном, вычитаем комиссию (`calculator.edge`).
4. **Проверка** — логируем сигнал, ждём исхода, сверяем (`backtest.py`).

## Три проверки в бэктесте — читай их так

- **Калибровка.** Если сканер говорит «60%», должно сбываться ~60%. Плывёт —
  эталон систематически врёт.
- **P&L.** Средний доход на ставку $1. Малое `n` (<100) не значит ничего:
  дисперсия огромна.
- **Brier vs рынок.** Сравнивает тебя не с нулём, а с самой рыночной ценой.
  Если ты не точнее рынка — ты не нашёл ценности, ты шумел. Самая честная
  и самая безжалостная строка.

## Честные ограничения

- Матчинг по названию — **только черновой фильтр**. Разные критерии закрытия
  превращают «вилку» в две независимые ставки. Проверяй пары глазами.
  `matcher.find_candidates` дополнительно режет пары по расхождению дат
  закрытия (`max_date_diff_hours`, по умолчанию 6ч) — это отсекает часть
  фантомов, но не проверяет совпадение источника истины/критериев.
- **Kalshi на практике (проверено на живых данных):** открытый листинг без
  фильтра на ~99.9% состоит из автосгенерированных parlay/combo-рынков —
  из 8000 просмотренных рынков нашлось 11 не-combo, и ни один не прошёл
  ценовой sanity-фильтр. Поднимать `max_pages` в этом режиме бесполезно.
  Рабочий путь — запрашивать конкретную `series_ticker` (список серий по
  категории: `get_kalshi_series("Crypto"/"Politics"/...)`); там комбо почти
  нет, и находятся нормальные двусторонние рынки. См. `matcher.py __main__`
  за рабочим примером (Polymarket "bitcoin" через `search_polymarket_markets`
  + Kalshi `KXBTCMAXMON`).
- **Числовые "лестницы" ($X) — текстовое сходство недостаточно.** Проверено
  на живых данных: `$90,000` матчился с `$97,500` вместо своего настоящего
  аналога — длинный шаблонный текст топит разницу в паре цифр. `find_candidates`
  теперь дополнительно требует точного совпадения суммы в `$...`, если она
  однозначно извлекается с обеих сторон (`extract_strike`).
- Комиссия в расчётах упрощена (плоский %). Реальная на Polymarket зависит
  от категории и максимальна у цены ~50c.
- De-vig простым делением слегка завышает фаворитов (для учёбы ок).
- API-поля и базовые URL со временем меняются — сверяйся с доками площадок.
- Обыграть эффективный рынок вручную и стабильно — трудно. Если бэктест это
  покажет, это не провал проекта, а его главный результат.

## Дисклеймер

Код учебный. Ставки — это азартные игры с реальным риском потерь. Ничего
здесь не является финансовым советом. Проверяй легальность площадок в своей
юрисдикции.
